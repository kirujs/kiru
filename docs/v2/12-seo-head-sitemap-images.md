# SEO, document head, sitemap, and images

Kiru centralizes document metadata in **route head layers**, optional per-page `head` exports, SSR serialization, and client head sync after navigations.

---

## Head layers

### Declarative (`RouteHeadMeta`)

On scopes/routes in tree:

- `title`, `description`, `keywords`, `robots`, `canonical`
- `openGraph`, `twitter`
- `extraMeta[]`, `links[]`, `jsonLd`

Resolved along ancestor chain via `routeMeta` / head merge utilities — **object replaces inherited** unless function form `(inherited) => ({ ...inherited, title: "..." })`.

### Runtime page head

Page module exports:

- `export const head = { title: "..." }` or
- `defineHeadContent(async (ctx) => ({ title: ctx.data... }))`

`pageHead.ts` distinguishes sync vs async vs static head for streaming (`isAsyncPageHead`, `isSyncPageHead`, `isStaticPageHead`).

Merged with route head: `mergeRouteAndPageHead`, `resolveMergedRoutePageHead`.

### Serialization

`serializeDocumentHead` → HTML fragment for `{{kiru_head}}`.

Streaming: `buildStreamDocumentHead` adds context, page data, i18n scripts.

### Client navigations

`syncDocumentHeadAfterCommit` / `documentHeadClient.ts` — updates `document.title` and meta after CSR/SSR navigations.

Tests: `documentHeadClient.test.ts`, `routeMeta.test.ts`.

## Placeholders

Dynamic segments in titles/descriptions support `{param}` substitution from route params during resolve.

## Site config & sitemap

`defineSiteConfig` (`site.ts`):

```typescript
export const site = defineSiteConfig({
  url: "https://example.com",
  sitemap: {
    changefreq: "weekly",
    priority: 0.8,
    include: ["/users/[id]"],
    exclude: ["/admin"],
  },
})
```

`buildSitemapXml(paths, site)` — XML string for robots.

`generateSitemapPaths` — static + optional SSR paths + included dynamic routes (requires `generateSitemapParams` on page).

Tests: `router.test.tsx` sitemap cases, `site.test.ts`.

## Images

**Removed in v2.0.** The experimental `<Image />` component, `kiru/image` export, Vite `router.images`, and Node `/_kiru/image` sharp optimizer were dropped so a unified pipeline can ship in v2.1+.

- **Today:** Use plain `<img>` and static assets; set `head.openGraph.images` / `twitter` to absolute URLs.
- **Planned:** [21-image-pipeline-adr.md](./21-image-pipeline-adr.md) — Node **sharp**, Cloudflare **resvg**, optional peer packages `@kirujs/image-sharp` / `@kirujs/image-worker`.
- **OG dynamic PNG routes:** Phase 3 on the same backend (after HTML image pipeline).

## robots.txt / manifests

Not generated by core — add static files in `public/` or custom server routes outside renderer.

---

## SEO checklist for apps

- [ ] Every public route has title + description (scope default + page override)
- [ ] Canonical URLs set on duplicate locale paths if needed
- [ ] `generateStaticParams` for all `static` dynamic routes
- [ ] Sitemap submitted only includes intended paths (`exclude` private areas)
- [ ] OG images use absolute URLs (static until image pipeline returns)
- [ ] SSR/SSG pages render critical meta in initial HTML (not client-only)
