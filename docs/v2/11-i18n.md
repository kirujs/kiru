# Internationalization

Kiru v2 integrates i18n into the **router** — locale prefixes, domain routing, detection redirects, message hydration, and locale-aware prerender paths.

Sources: `packages/lib/src/router/i18n/`, `i18nContext.tsx`, `prepareAppForUrl` locale branches.

---

## Configuration

`createI18nConfig` / `InternationalizationConfig`:

| Option | Purpose |
|--------|---------|
| `locales` | Supported locale codes |
| `defaultLocale` | Fallback |
| `localePrefix` | `always` \| `never` \| `as-needed` |
| `localeDetection` | Accept-Language / cookie on `/` |
| `localeCookie` | Default `KIRU_LOCALE` |
| `domains` | Map host → default locale |
| `invalidLocale` | `redirect` \| `not-found` for unknown prefix |

`getI18nLocaleRouting` derives URL splitting rules used by matcher and `Link`.

---

## URL splitting

`splitAppPathname` / `splitAppPathnameDetailed` (`i18n/routing.ts`):

- Strip locale prefix for `matchRoute`
- Handle wrong-domain redirects
- Invalid locale → redirect or 404 per config

CSR initial load may `navigateInternal` replace URL when detection fixes locale (`csr.ts`).

---

## SSR renderer behavior

`prepareAppForUrl`:

1. `tryLocaleDetectionRedirect` — e.g. `/` → `/en` when detection enabled
2. `shouldRejectInvalidLocale` — not-found vs redirect
3. `loadI18nMessages` for active locale
4. Serialize `HydratedI18nPayload` via `serializeI18nScript` in head

Tests: `i18n.test.ts` — detection redirect, serverLoader locale in context, invalid locale not-found.

---

## Client runtime

- `createI18nRuntime` on router create
- `readHydratedI18n` from script tag on hydrate
- `useI18n()` / `I18nProvider` / `I18nReactiveRoot`
- `ensureClientI18nReady` before mount

Locale change on navigation reloads messages when prefix changes.

---

## Prerender expansion

`expandPrerenderTargets` (`i18n/expandPaths.ts`):

- One HTML file per locale public URL when prefixes required
- `storageKey` may include `locale::path` for cache
- `diskPath` disambiguates collisions on disk

SSG e2e: `e2e/ssg/cypress/e2e/i18n.cy.ts`, CSR: `e2e/csr/cypress/e2e/i18n.cy.ts`.

---

## HTML template

Templates may use `{{kiru_locale}}` for `<html lang="…">` — validated in `htmlTemplate.ts` (warn if literal lang conflicts).

---

## Loader / middleware context

`loaderI18nFields` adds `locale`, `locales`, `defaultLocale` to loader context.

Middleware receives full pathname in locale-aware public form via `buildMiddlewareLocation`.

---

## Typing

Augment messages:

```typescript
declare module "kiru/router" {
  interface Internationalization {
    config: typeof i18n
  }
}
```

`useI18n()` becomes typed against your config.

---

## Gaps vs dedicated i18n libraries

- No ICU message format built-in — JSON message maps
- No RTL-specific layout helpers
- No automatic hreflang generation (you can add via `head` layers)
