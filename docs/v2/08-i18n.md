# Internationalization (i18n)

Locale-aware URLs, message bundles, SSR hydration, and hreflang sitemaps — Tier 3 wave 1. Implementation: `packages/lib/src/router/i18n/`.

## Config

```ts
// src/i18n.ts
import { createI18nConfig } from "kiru/router"

const i18n = createI18nConfig(["en", "fr"], {
  localePrefix: "as-needed",   // default
  invalidLocale: "redirect",
  localeDetection: true,
  localeCookie: "KIRU_LOCALE",
  detectPaths: ["/"],
})({
  default: "en",
  load: {
    en: () => import("./i18n/en.json"),
    fr: () => import("./i18n/fr.json"),
  },
})

export default i18n
```

### Routing policies

| Option | Behavior |
|--------|----------|
| `localePrefix: "always"` | `/en/about`, `/fr/about` |
| `localePrefix: "as-needed"` | Default locale omits prefix (`/about` = en) |
| `invalidLocale: "redirect"` | Unknown `/xx/...` → default or detect |
| `localeDetection` | `Accept-Language` / cookie on `detectPaths` |

Logical routes stay `/about` in `routes.ts`; router strips/adds prefix via `localeRouting.ts` + `splitAppPathname`.

## Type-safe `useI18n`

```ts
declare module "kiru/router" {
  interface Internationalization {
    config: typeof i18n
  }
}
```

```tsx
const { t, locale, setLocale } = useI18n()
return () => <h1>{t("home.title")}</h1>
```

`DotPath` inference from JSON default export (`i18n/translate.ts`, `augmentation.ts`).

## Wiring per mode

```ts
// CSR / SSG / SSR client
createRouterApp({ routes, i18n, ... })

// SSR server
createRenderer({ routes, i18n, ... })
```

### SSR hydration script

`serializeI18nScript` embeds active locale + messages in `<script k-i18n>` so first paint matches server translation.

### CSR without SSR payload

`ensureClientI18nReady` awaits `i18n.load[locale]()` before mount when no `k-i18n` in document.

## `Link` locale prop

```tsx
<Link href="/about" locale="fr">Version française</Link>
```

Resolves href with prefix policy (`navigation.ts` / `resolveHref`).

## Static paths + i18n

`generatePublicStaticPaths` expands each static pathname per locale (`expandPaths.ts`).

SSG builds separate HTML files:

- `/about` (en, as-needed default)
- `/fr/about`

## Site config + hreflang

```ts
export const site = defineSiteConfig({
  url: "https://example.com",
  locales: ["en", "fr"],
  sitemap: true,
  robots: true,
})
```

Sitemap generation includes alternate links when `locales` set (see `site.ts` + tier-3 doc).

## Loader context

When i18n enabled, loaders receive:

```ts
{ locale, locales, defaultLocale }
```

Use for locale-specific API fetch.

## Use-case examples for docs

### Single default locale site

`createI18nConfig(["en"])({ default: "en", load: { en: () => import("./en.json") } })` — still get typed `t()` paths.

### Marketing site FR/EN

`localePrefix: "always"` + prerender all locale paths + hreflang sitemap.

### Locale switcher in layout

```tsx
<button onClick={() => setLocale("fr")}>FR</button>
```

Triggers bundle load + URL update per policy.

### SSR + cookie detection

Server reads `KIRU_LOCALE` cookie in `getRequestContext` aligned with `localeCookie` name.

### Invalid locale URL

User visits `/de/about` — `invalidLocale: "redirect"` sends to `/en/about` or detected locale.
